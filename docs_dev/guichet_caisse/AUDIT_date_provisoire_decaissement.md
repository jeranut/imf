# Audit — date de décaissement provisoire (lecture seule)

1. **Origine du défaut** : `_compute_disbursement_date_planned_default()`, `models/microfinance_loan.py:3226-3245` — `planned = base + self._period_delta()` (base = aujourd'hui), au lieu de `planned = base`. Générique (toutes périodicités passent par `_period_delta()`, pas de cas spécial mensuel) : hebdomadaire/quinzaine ont le même défaut par construction.
2. **Sémantique actuelle** : `disbursement_date_planned` posée par `action_activate()` (ligne 3260-3261, seulement si ni confirmée ni déjà renseignée) ou `_activate_with_auto_confirm()` (3284-3285, chemin direct sans wizard) ; `disbursement_date_confirmed` posée par le wizard `microfinance.loan.activation.confirm.wizard` ou directement par `_activate_with_auto_confirm()`. Usages : ancre de génération d'échéancier (3) et condition du cron `cron_release_ready_disbursements` (libère le crédit pour décaissement guichet une fois `disbursement_date_planned` atteinte) + affichage dashboard "Décaissements en attente".
3. **Génération** : point de départ = `disbursement_date or disbursement_date_planned or approval_date or application_date or aujourd'hui` (`_build_installment_commands`, ligne 2498) ; 1ère échéance = `start + 1×période` (ligne 2548, boucle `idx=1..term`), arrondi jour de collecte via `_roll_forward_to_collection_day` **à chaque échéance**, déjà correct. Génération déclenchée à **l'activation** (`_do_activate` → `_regenerate_schedule_from_planned_disbursement`, ligne 3291-3326), pas au décaissement réel.
4. **À `action_process_disbursement`** (ligne 3328-3388) : `disbursement_date` posée (3377), puis `_regenerate_schedule_from_disbursement()` **toujours** rejouée (3386), avec garde paiement déjà imputé (`inst.paid_principal/interest/penalty`, ligne 3406-3410 → `UserError` bloquant). Le "si elle diffère" demandé n'est pas testé (régénération inconditionnelle) — fonctionnellement neutre si date inchangée, mais à noter.
5. **Prêts en base MOWGLI** (`state='active'`, `disbursement_date IS NULL`) : 8 au total — AD/000003,004,005 (hebdo, écarts 8-18j vs activation), SY/000004 (hebdo, 10j), MS/000001,002,003 (hebdo, 2-3j), **AD/000011** (mensuel, écart **0j** — `disbursement_date_planned` déjà = `activation_date` en base, contrairement aux 04/11/2026 que vous rapportez avoir vu à l'écran). Écart à clarifier avec vous avant migration (incohérence valeur affichée / valeur stockée sur ce dossier précis) — aucun des 8 n'a de paiement ; aucun n'est IS/000289 ni IS/001076 (hors périmètre, non touchés).
6. **Consommateurs de la date provisoire** : wizard de confirmation, vue formulaire crédit, dashboard (liste d'attente, affichage seul, `static/src/xml/microfinance_loan_dashboard.xml`), cron de libération. **Aucun usage dans microfinance_payroll_loan** (qui lit `disbursement_date`/`due_date`/`residual_amount`, jamais `disbursement_date_planned`) — impacté seulement indirectement si les dates d'échéance changent après correction, pas de valeur de test à ajuster a priori.
